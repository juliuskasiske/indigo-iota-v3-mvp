A guided tour of the client-demo-v1 repository

How this whole thing works

This is a plain-language map of your codebase — what the pieces are, how a click in the browser travels all the way to the database and back, and which file does what. It assumes you can read Python but have not met most of the surrounding concepts. We build those up first.

Read it in order the first time — each page leans on the one before. After that, jump around using the bar at the top. Every diagram is rendered live and works offline.

What is this product, in one breath?

Indigo Iota is a "project brain" for consultancies. It quietly reads the email, files, and chat of a client engagement, and keeps a living, organised memory of it: pages about each person, company, and project, a map of how they connect, and a search box you can ask questions of — with citations back to the source. Each customer's memory lives in its own separate database so no two customers' data ever touch.

The shape of the repository

At the very top, the project is four folders. Almost everything else lives inside them.

client-demo-v1/
├── backend/     the "engine": Python (FastAPI) + the databases. Does the real work.
├── frontend/    the "face": the Next.js website you click around in.
├── infra/       the "plumbing": Docker recipes to run it locally and in production.
└── docs/        notes & this explainer (never shipped to customers).
Think of a restaurant. frontend is the dining room you see and touch. backend is the kitchen that actually cooks. infra is the building, wiring, and gas lines that let the kitchen run. docs is the staff binder in the back office.
